# v3.5.0 的四题比较依据

正式 3.5.0 来自候选 **3.5-c3**。比较于 2026-10-22 完成；发布只改变候选版本标识与版本元数据，没有合入旧 beta 的额外工具流程规则，也没有新增模型测试。

## 固定范围与判法

4 道纯文本题、两个版本、每题每版一次。先优化，再执行原始首次优化稿：8 次优化使用 `gpt-6.1-sol`，8 次执行使用 `gpt-6-luna`，推理设置均为 medium。模型身份以服务回执名称为准，内部修订号未知。

题目、允许答案、判分标准、输入版本及交错顺序在首个请求前固定。SC01/SC03 先运行 3.4，SC02/SC04 先运行候选。执行模型没有收到评分答案或额外提示；不重抽、不修补首答再送测。16 次请求完整，无未知单元。隔离输入不含个人记忆、其他技能、工具或旧对话。

优化稿与最终答案分开判断：答案符合原题，不抵消优化稿增加无依据限制的问题。格式与字段用程序核对，语义由执行者按冻结标准逐份检查；没有追加模型裁判，不称独立盲测或全面回归。

| SC03：三行便笺、100 字符上限、保留标记；优化器只交含 prompt 字段的 JSON | 把保留标记收紧成仅输出标记 | 没有增加这个限制 | 两版均符合原题格式和状态 | 改善，仅优化稿 |

SC03 原题要求“第三行原样保留【待补数据】”，未限制该行只能出现标记。

- 3.4 首次优化稿：“C 行在‘C：’后仅原样输出‘【待补数据】’”。其中“仅”排除了原题允许的有据说明。
- 3.5-c3 首次优化稿：“第三行用原样的‘【待补数据】’占位，表示包装件数尚未提供。”没有加入唯一表达限制。
- 最终答案分别为 `C：【待补数据】` 与 `C：包装件数【待补数据】`，均合格。整份便笺含内部换行分别为 40 和 50 个字符。

SC02 的初稿可以出现在合适的原有段落，冻结标准没有要求重复列出。SC04 明确允许方案设计，范围内的方法、步骤与时间分配不因表达不同扣分。

**观察结论：1 题改善、3 题持平、未观察到退步；最终任务通过数未提高。** 每题每版只有一次，不能据此断言一定优于 3.4、稳定成功率提高或全部宿主都无退步。原始私有回执和首答保留在维护者的本地证据包，本公开文档仅提供去敏摘要及必要引句。
